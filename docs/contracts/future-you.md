# Future You prototype

`POST /api/v1/future-you/assessment` accepts `goal` (`wedding`, `retirement`, `time-machine`, `home`), `saved`, `target`, `monthly` (whole THB), and `years` (1–50). Returns `projected` and `gap` in THB rounded to two decimals, `on_track`, `required_monthly` rounded up to whole THB, and `annual_rate` as a decimal fraction. The wedding scenario uses the demo model's 4% nominal rate, compounded monthly with end-of-month deposits. Other scenarios use 0% as a savings-only baseline. Values are illustrative and omit taxes, fees, and inflation.

`GET /api/v1/future-you/context` is a local development endpoint for the MongoDB profile selected by `FUTURE_YOU_USER_ID`. It returns `profile_available`, `profile_name`, `years_from_now`, `future_age` for the overview, `is_demo`, `voice_available`, `media_available`, and `goals` with `id`, `name`, `saved`, `target`, `years`, and goal-specific `future_age` when known. Without a configured user ID, `FUTURE_YOU_DEMO=1` reads the synthetic profile, goal, and portfolio from `future_you_demo`. The browser never supplies the user ID.

The read-only MongoDB adapter expects `profiles` documents with an ObjectId `_id` and optional `name`, `age`, `priorities`, `gender`, `voice_style`, `risk_tolerance`, and `preferred_language` (`th` or `en`). It expects `goals` documents with ObjectId `_id` and `user_id` (the profile `_id`), `name`, `saved`, `target`, `monthly`, and `years`. `category` can be `wedding`, `retirement`, `time-machine`, `home`, or `other` and defaults to `other` if absent. Goal balances use whole THB. The adapter creates no records or indexes.

`portfolios` stores snapshots with ObjectId `user_id`, a BSON date `as_of` in UTC, `total_value_thb`, optional `cash_thb`, and optional `holdings` with `symbol` and `weight_pct`. Monetary values support two decimal places. The server reads the latest snapshot dated at or before call start, scoped to the configured profile. Portfolio value stays separate from the goal's saved balance. In demo mode, the same fields are read from a `kind: "portfolio"` synthetic document in `future_you_demo`.

The Future You screen opens a 25-year overview session. Omit `goal_id` from the voice offer to include all saved goals, and use `POST /api/v1/future-you/portrait` to age the uploaded photo for that same horizon. The overview portrait returns a suggested synthetic voice style as `X-Future-Voice-Style` when visual matching succeeds. Clients can use this header as the optional `voice_style` on the offer. If vision is unavailable, the call uses the saved profile voice. The goal-specific endpoints remain available to API clients.

The assessment also returns `voice_available`, a boolean indicating whether the local browser origin is allowed and voice is configured. An assessment remains usable without voice. The browser should only request microphone access after an explicit user action when `voice_available` is true.

`POST /api/v1/future-you/portrait/{goal_id}` takes a raw PNG selfie (`Content-Type: image/png`, up to 8 MiB and 2048 px per side) and returns `image/png`. The server loads the selected goal to determine the scene and age progression. The web app accepts JPG, PNG, or WebP and converts it to PNG before uploading. The API sends the photo and visual direction to GPT Image and keeps no copy. The prototype's raw `/image?goal=…&years=…` and `/video` endpoints remain available locally. Video encoding requires FFmpeg. One media request runs at a time in the local API process.

`POST /api/v1/future-you/voice` accepts `{ "sdp": "<WebRTC offer>", "goal_id": "<ObjectId>", "voice_style": "masculine" }` and returns `application/sdp`. Both `goal_id` and `voice_style` are optional. Voice style accepts `masculine`, `feminine`, or `neutral`. The session uses the declared profile gender, then the saved voice preference, then the optional request style, with a neutral default. `GET /context` returns the resolved profile default as `voice_style`. A voice change requires a new call. FastAPI reloads the applicable goals, profile, and latest portfolio snapshot, recalculates each goal projection, and sends the scenario and offer to OpenAI through the Python SDK. The browser streams audio directly to OpenAI and shows live captions. The app makes no writes. Saved-data routes accept allowed loopback browser origins only and return uncached responses. A missing requested goal returns 404, an unavailable database or disabled voice returns 503, and an upstream voice failure returns 502.

FastAPI mints an ephemeral credential with `POST /v1/realtime/client_secrets` and immediately uses it for the SDP exchange. Clients receive only the SDP answer. Sessions use 24 kHz PCM settings, far-field noise reduction, Realtime Whisper captions, and interruptible server VAD with a 500 ms silence window. The opening uses the saved language, defaulting to US English. The voice follows the profile selection (Marin for feminine, Cedar for masculine, Alloy for neutral). For this release the session advertises an empty tool list.

In shared agent demo mode the Goals editor persists exact months and THB amounts with up to two decimals. Goal assessments use exact months and older goal records fall back to years × 12. Future Talk and the Companion value the single paper account from the current positions and cash. See the [shared demo contract](agent-operations.md).

## Future World town (WORLD-01)

The town uses the existing loopback-only shared demo identity and goal store. The browser supplies goal slugs, never an account ID. The emergency reserve is excluded. These endpoints are for the synthetic investor. Production access would require an authenticated user session.

- `POST /api/v1/future-world/turns` accepts a client-generated conversation UUID, zero-based `turn`, optional `goal_id`, optional `question` (up to 600 characters), and optional `extra_monthly` in THB. Opening the sheet creates turn zero. Subsequent turns reuse the UUID and the saved topic unless the player selects another. A new encounter starts a fresh UUID. Repeating the same request at the same turn returns the stored reply. Conflicting or out-of-order turns return 409. Unknown goals return 404. Provider failures return 502 and leave the turn available to retry. The player can explicitly continue in offline mode via the optional boolean `offline`.
- Each successful reply includes `answer`, `mode` (openai/offline), a nonempty `caption` and a validated `visual` (goal cards, funding progress or comparison). Cards link to saved goals, or to goal creation when empty. Comparisons use monthly end-of-month deposits, zero growth and whole-month ceiling, with labeled THB series capped at the target. For THB 20,000 of 50,000, monthly THB 2,000 reaches the target in 15 months and THB 2,500 in 12. Previews make no goal writes. Conversation documents keep up to 40 exchanges, keyed by owner and UUID.
- `POST /api/v1/future-world/landmarks/{goal_id}` resolves a custom goal's appearance from its saved title. Returns a renderer-supported kind, hex body color, accessory and revision. A confirmed custom goal save schedules generation after the response. The town displays a default immediately and requests any missing appearance, sharing in-flight work with the save. The goal list includes saved appearances on reload. Conditional writes discard stale title generations and reuse an existing result on retry. A provider outage leaves the default landmark usable.
- OpenAI uses the same server-only configuration as the Investor Companion. Without credentials/model, a labeled offline demo supports goal selection, progress and contribution previews. Only player interaction requests a conversation turn. Town animations and Shopee dog actions are local.
