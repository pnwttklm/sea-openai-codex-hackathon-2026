# Future You prototype

`POST /api/v1/future-you/assessment` accepts `goal` (`wedding`, `retirement`, `time-machine`, `home`), `saved`, `target`, `monthly` (whole THB), and `years` (1–50). Returns `projected` and `gap` in THB rounded to two decimals, `on_track`, `required_monthly` rounded up to whole THB, and `annual_rate` as a decimal fraction. The wedding scenario uses the demo model's 4% nominal rate, compounded monthly with end-of-month deposits. Other scenarios use 0% as a savings-only baseline. Values are illustrative and omit taxes, fees, and inflation.

`GET /api/v1/future-you/context` is a local development endpoint for the MongoDB profile selected by `FUTURE_YOU_USER_ID`. It returns `profile_available`, `profile_name`, `years_from_now`, `future_age` for the overview, `is_demo`, `voice_available`, `media_available`, and `goals` with `id`, `name`, `saved`, `target`, `years`, and goal-specific `future_age` when known. Without a configured user ID, `FUTURE_YOU_DEMO=1` reads the synthetic profile, goal, and portfolio from `future_you_demo`. The browser never supplies the user ID.

The read-only MongoDB adapter expects `profiles` documents with an ObjectId `_id` and optional `name`, `age`, `priorities`, `gender`, `voice_style`, `risk_tolerance`, and `preferred_language` (`th` or `en`). It expects `goals` documents with ObjectId `_id` and `user_id` (the profile `_id`), `name`, `saved`, `target`, `monthly`, and `years`. `category` can be `wedding`, `retirement`, `time-machine`, `home`, or `other` and defaults to `other` if absent. Goal balances use whole THB. The adapter creates no records or indexes.

`portfolios` stores snapshots with ObjectId `user_id`, a BSON date `as_of` in UTC, `total_value_thb`, optional `cash_thb`, and optional `holdings` with `symbol` and `weight_pct`. Monetary values support two decimal places. The server reads the latest snapshot dated at or before call start, scoped to the configured profile. Portfolio value stays separate from the goal's saved balance. In demo mode, the same fields are read from a `kind: "portfolio"` synthetic document in `future_you_demo`.

The Future You screen opens a 25-year overview session. Omit `goal_id` from the voice offer to include all saved goals, and use `POST /api/v1/future-you/portrait` to age the uploaded photo for that same horizon. The overview portrait returns a suggested synthetic voice style as `X-Future-Voice-Style` when visual matching succeeds. Clients can use this header as the optional `voice_style` on the offer. If vision is unavailable, the call uses the saved profile voice. The goal-specific endpoints remain available to API clients.

The assessment also returns `voice_available`, a boolean indicating whether the local browser origin is allowed and voice is configured. An assessment remains usable without voice. The browser should only request microphone access after an explicit user action when `voice_available` is true.

`POST /api/v1/future-you/portrait/{goal_id}` takes a raw PNG selfie (`Content-Type: image/png`, up to 8 MiB and 2048 px per side) and returns `image/png`. The server loads the selected goal to determine the scene and age progression. The web app accepts JPG, PNG, or WebP and converts it to PNG before uploading. The API sends the photo and visual direction to GPT Image and keeps no copy. The prototype's raw `/image?goal=…&years=…` and `/video` endpoints remain available locally. Video encoding requires FFmpeg. One media request runs at a time in the local API process.

`POST /api/v1/future-you/voice` accepts `{ "sdp": "<WebRTC offer>", "goal_id": "<ObjectId>", "voice_style": "masculine" }` and returns `application/sdp`. Both `goal_id` and `voice_style` are optional. Voice style accepts `masculine`, `feminine`, or `neutral`. The session uses the request override, then the saved voice preference, then the declared profile gender, with a neutral default. `GET /context` returns the resolved profile default as `voice_style`. A voice change requires a new call. FastAPI reloads the applicable goals, profile, and latest portfolio snapshot, recalculates each goal projection, and sends the scenario and offer to OpenAI through the Python SDK. The browser streams audio directly to OpenAI and shows live captions. The app makes no writes. Saved-data routes accept allowed loopback browser origins only and return uncached responses. A missing requested goal returns 404, an unavailable database or disabled voice returns 503, and an upstream voice failure returns 502.
